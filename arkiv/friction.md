# Integration feedback

Recorded during implementation starting 2026-10-30 Asia/Kolkata (2026-10-29 UTC), with Rabdi migration preparation on 2026-10-31. Both are pre-event work.

- The original SDK 0.8.1 integration targeted Tiramisu `7738577`. Current and older-network pages now identify Rabdi `7794095` as its replacement and say entities do not carry over. The still-accessible Tiramisu page and stale generated API references made the transition difficult to identify. A versioned network/API compatibility table would help.
- This migration required more than a chain constant: latest-only queries replace `atBlock`, offset pagination replaces cursors, and named schemas replace top-level payload/content type. The reader now uses twelve typed attributes, including public payload bytes, while preserving the logical content hash. Tests reject legacy wire records and prevent old order references from being reinterpreted on Rabdi.
- Fresh registry metadata and the SDK 1.0.0 tarball resolved the SDK documentation mismatch. Its `rabdi({accessKey})` factory, `./schema` exports and `createEntity(schema, values, {expiration})` signature were checked directly. The tarball SHA-256 is `501c8165dff1187ecbde25ab84ba3af193fcd8025581610b5486762ce427d285`. A focused test uses the real SDK encoder and decodes the resulting transaction data against the documented ABI without sending to a network.
- Native `expiresAt` is a hexadecimal block height, while this application also needs a UTC offer deadline. Explicit examples showing both clocks help prevent treating block height as Unix time. The reader tests the two boundaries separately.
- Typed attributes require different JSON wire encodings: `u64` is a hexadecimal quantity and `addr` is an address. A numeric string with type `str` cannot replace `u64`. Independent RPC fixtures cover these distinctions.
- SDK 1.0.0 reads one entity with `arkiv_getEntity`. The independent Go reader uses a latest key-predicate query to obtain a response block and brackets it with chain/head checks. Neither path invents historical-read support. The browser verifies exact owner, attributes and expiry after receipt confirmation; readback failures stay uncertain without an automatic second write.
- SDK 0.8.1 package metadata returned no license field, and the upstream root `LICENSE` URL returned 404 during the original inspection. The inspected SDK 1.0.0 package metadata also has no license field. This remains a dependency provenance question, not a claim that no license exists elsewhere. The central dependency owner has been notified.
- The historical Tiramisu public reads succeeded but returned no matching v1 offers. They prove no Rabdi availability. This migration performed no live RPC, wallet, faucet or write actions. Current offer availability, funding, wallet compatibility and event qualification need separate evidence; a blocked request alone does not establish a network outage.
